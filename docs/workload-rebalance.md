## Daily dependency-aware workflow

Open **Performance → Workload and next actions** for each person.

1. Finish or resolve existing work in progress before pulling another item.
2. Otherwise, candidate tasks have no unfinished ticket-ID prerequisites, are in a started sprint, are not explicitly blocked and are not conditional work. Confirm external inputs before starting.
3. The full queue shows waiting ticket IDs and downstream impact, ordered by due date, priority and downstream impact. A separate review/support list reserves work on other owners’ tickets.
4. Design/API fixtures allow preparation; they do not prove live acceptance. Model artifacts precede serving integration, APIs precede live UI, legal clearance precedes real-data onboarding, and versioned QA evidence precedes release.
5. Saved statuses and assignments affect the queue when rendered. If a lead is edited, review contributor allocations too: specialist work does not automatically transfer with the lead.

This is a work-pull and handoff plan, not a resource-feasible calendar or an automatic approval system. Same-day handoffs require actual input and review evidence. Unknown free-text dependencies remain visible. No team messages, access changes or status updates were made.
